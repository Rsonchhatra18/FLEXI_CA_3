## 📝 Summary

- **Prompt chaining**: Split a task into a fixed series of LLM calls, feeding each output into the next; adds latency but boosts accuracy and lets you insert cheap validation “gates” between steps.  
- **Routing**: Classify the initial input and dispatch it to specialized prompts or models (e.g., refund vs. technical queries), allowing cheap models for easy cases and larger models for hard ones.  
- **Tool use (ReAct)**: Provide the model with described functions (search, calculator, DB query, etc.); the model emits a structured tool call, the program runs it, returns the result, and the model continues reasoning.  
- **Evaluator‑optimizer (reflection)**: Generate an answer, then a second LLM call evaluates it against explicit criteria; if it fails, the generator revises using the feedback, looping up to a set iteration limit.  
- **Orchestrator‑workers**: A central LLM dynamically breaks a complex problem into unknown sub‑tasks, assigns each to worker agents (LLM calls or tools), and synthesises their outputs—useful for coding across many files or multi‑source research.  
- **Pattern selection tip**: Start with a single well‑prompted call + retrieval; add chaining or routing for clear stages, tools for external data/actions, reflection loops for quality checks, and full orchestration only for open‑ended problems. Always log each step for debugging.

## 🔑 Key Terms

- **Prompt chaining** – A sequence of LLM calls where each call’s output feeds the next step, allowing complex tasks to be broken into simpler, more accurate sub‑tasks.  
- **Routing** – The initial classification of input that directs it to specialized handlers or models, keeping downstream prompts focused and optimizing resource use.  
- **Tool use** – Providing the model with defined functions (tools) it can invoke, enabling actions like calculations, web searches, or database queries within a reasoning loop.  
- **Evaluator‑optimizer (reflection)** – A two‑step loop where one LLM generates an answer and a second LLM evaluates it against explicit criteria, feeding back revisions until the answer passes.  
- **Orchestrator‑workers** – A central LLM that dynamically decomposes a complex task into sub‑tasks, assigns each to worker agents, and then synthesizes their results.

**Q1. Which pattern involves breaking a task into a fixed sequence of LLM calls where each output becomes the next input?**  
- A) Routing  
- B) Prompt chaining  
- C) Tool use  
- D) Orchestrator‑workers  

*Answer: B – Prompt chaining strings together multiple calls in a predetermined order.*

**Q2. In the routing pattern, what is the primary benefit of sending “easy” questions to a smaller model?**  
- A) It reduces latency for all requests.  
- B) It ensures higher accuracy for complex queries.  
- C) It saves computational cost while keeping downstream prompts focused.  
- D) It allows the small model to learn from the large model.  

*Answer: C – Small models handle cheap, simple cases, lowering cost and keeping downstream prompts specialized.*

**Q3. Which component is essential for a model to correctly use a tool in the tool‑use pattern?**  
- A) A large temperature setting.  
- B) A list of tool names, descriptions, and typed arguments.  
- C) A pre‑written script that calls the tool.  
- D) An external API key.  

*Answer: B – The model selects a tool by reading its description and argument schema.*

**Q4. In the evaluator‑optimizer (reflection) pattern, what prevents the system from looping forever?**  
- A) Using a deterministic random seed.  
- B) Limiting the number of iterations.  
- C) Switching to a different LLM after each failure.  
- D) Disabling the evaluator after the first pass.  

*Answer: B – A maximum iteration count stops endless revision cycles.*

**Q5. How does the orchestrator‑workers pattern differ from prompt chaining?**  
- A) It always uses a single LLM call.  
- B) The sub‑tasks are defined at design time.  
- C) The orchestrator decides sub‑tasks at runtime and may create an unknown number of workers.  
- D) It never requires a final synthesis step.  

*Answer: C – The orchestrator dynamically creates and assigns sub‑tasks, unlike the fixed sequence of prompt chaining.*
